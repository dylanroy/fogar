Your own models · a new tab for Chrome

Your key, your model. Nobody in between.

The model on your device answers by default. When you want a bigger one, bring your own key: Claude, OpenAI, OpenRouter, Gemini, Groq, or Ollama and LM Studio running on your computer. Your browser talks straight to the provider. Fogar has no server, so there is no copy of your key or your conversations anywhere but here.

Straight talk

Your key is yours to guard.

The rest of Fogar is a new tab that answers from a model running in your browser. See what leaves in each mode.

  • Keys are kept in Chrome’s extension storage on this device, like any extension setting. They are not encrypted. Anyone who can use your Chrome profile can find them.
  • The Settings backup file includes your Settings cloud key, because it is your file. Keep it like a password.
  • A cloud provider sees everything you send it, under its own terms. Fogar keeps no copy, but it cannot speak for them. For nothing to leave, use the device model, Ollama, or LM Studio.
  • The ask box’s Settings endpoint speaks only the OpenAI format. Claude through the Messages API lives in the LLM Chat, Writing, and Canvas widgets; for Claude in the ask box, go through OpenRouter.
  • Fogar can be granted any HTTPS address and servers on this computer. A plain-HTTP server elsewhere on your network is outside what it can ask for.
Questions

Fair questions, short answers.

Does my key or my chat go through a Fogar server?

No. There is no Fogar server. The new tab sends each request straight to the endpoint you configured, with your key, and to nowhere else. The network ledger in Settings counts every request the page makes, by host.

Can I use Claude?

Yes. In the LLM Chat widget, add the Anthropic preset and paste a key from console.anthropic.com. Fogar talks to the Messages API directly from your browser. The Writing and Canvas widgets can pick the same profile. The ask box’s cloud endpoint speaks the OpenAI format, so for Claude there, use OpenRouter.

Can I use Ollama or LM Studio?

Yes, with no key. The presets point at localhost:11434 for Ollama and localhost:1234 for LM Studio, and Fetch models lists what is installed or loaded. The Settings cloud endpoint takes Ollama too, so the ask box can use it. The server has to be running.

Why does Chrome ask for permission when I save?

Fogar cannot know your endpoint in advance, so it lists none at install. When you save or fetch models, it asks Chrome for access to that one origin, and only that one. If you decline, the profile is still saved, and Fogar says the permission was not granted.

Where is my key stored?

In Chrome’s extension storage on this device, unencrypted, like any extension setting. It is sent only to the endpoint it belongs to. Remove the profile, or clear the field in Settings, and it is gone.

Do conversations persist?

Yes. Each LLM Chat widget keeps its conversation in extension storage, so it is there on your next tab. It holds the most recent 60 messages or 30,000 characters, whichever comes first. New chat clears it.

Install

Add to Chrome

Fogar is on the Chrome Web Store. One click to add it, and it updates itself from there. Then open a new tab.

Add to Chrome

Free, from the Chrome Web Store. Brave, Arc, and Edge install from it too.

On your phone, or not on Chrome? The same Fogar runs as a web app at app.fogar.ai. Open it once with a connection, add it to your home screen (Safari: Share, then Add to Home Screen; Chrome: the menu, then Add to Home screen), and set it up from there; after that it works offline. The widgets that need Chrome’s own APIs, Sessions, bookmarks, Inbox, Feed, Jira, and Agenda, stay on the desktop.

Loaded the zip before the listing went live? The store copy has a different extension ID, so your data will not follow on its own. Three steps move it over.

  1. In your current Fogar, open Settings and click Download a backup.

    Todos, notes, recipes, widgets, sessions, and settings go into one file.

  2. Add Fogar from the store.

    It opens on your next new tab, empty.

  3. Open its Settings and Restore from a backup.

    Once it looks right, remove the old copy in chrome://extensions.

Can't use the store? The same build is here as a zip: unzip it, turn on Developer mode in chrome://extensions, and Load unpacked. It will not update itself.
