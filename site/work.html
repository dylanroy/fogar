Work inbox · a new tab for Chrome

Unread mail, open issues.
Before you open either.

The Inbox widget shows your unread Gmail on every new tab. The Jira widget shows the issues any JQL query returns. Both are read-only, both run from your browser with your own sign-in or token, and nothing goes through a Fogar server.

Each site is requested as an optional permission when you save the widget. The Gmail API path also needs Chrome’s identity permission, asked only when you click Connect Gmail.

How it works

Pick a connection. Set a filter. Glance.

Inbox, the easy way

Add widget, then Inbox, then “Gmail, unread feed”. That is it. To show a slice, make a Gmail filter that applies a label and name the label here. Several Google accounts? Set the account number, as in mail.google.com/mail/u/1.

no setup · unread only · one label as the filter

Inbox, any search

Choose “Gmail API, your own client”. In Google Cloud, create a project, enable the Gmail API, add a Web application client with the redirect address Fogar shows, add yourself as a test user, and paste the client id. Then any search works: from:stripe.com newer_than:7d.

about five minutes · your project, your key

Jira

Add widget, then Jira. Paste your site, your email, and an API token from id.atlassian.com. Leave JQL blank for your unresolved issues, most recently updated first, or paste any query: a sprint, a saved filter, a team.

read-only · up to 50 issues · fetched again after five minutes
Straight talk

A glance, not a client.

The rest of Fogar is a new tab that answers from a model running in your browser. See what leaves in each mode.

  • Both widgets are read-only. You cannot reply, archive, comment, or move an issue. Click a row and it opens in Gmail or Jira.
  • The Gmail feed lists only unread mail, and only for the Google account signed in to this browser. Sign out of Gmail and the widget asks you to sign back in.
  • Fogar ships no Google client of its own. Gmail’s read scope needs a yearly security audit for a published app, so the search option runs on a client you create. Google shows an “unverified app” screen once; that is your own project.
  • The Gmail API permission Google grants is read access to your whole mailbox, even though Fogar asks only for headers and snippets.
  • Your Jira token lives in Chrome’s extension storage on this device, is sent only to your Jira site, and is included in the backup file you export from Settings. Treat that file like the token.
Questions

Fair questions, short answers.

Does my mail go through a Fogar server?

No. There is no Fogar server. Your browser asks Gmail or Jira directly, and the list it gets back is kept in Chrome’s extension storage on this device.

Why does the unread feed need no sign-in?

Gmail publishes your unread mail as a feed for whichever account is signed in to this browser. Fogar fetches it with that session, the same way a Gmail tab would. If you are signed out, the widget tells you to open Gmail and sign in.

Why would I set up my own OAuth client?

For any Gmail search and for read as well as unread mail. Google treats Gmail read access as restricted, so Fogar does not ship a client. You create one in your own Google Cloud project, free, in about five minutes, and paste its id.

Can it show read mail or a specific sender?

The unread feed shows unread mail only. Either connection can also narrow to messages whose sender or subject contains a word you choose. For read mail or full Gmail search syntax, use the Gmail API option.

Does the Jira widget work with Jira Server or Data Center?

Yes. For a site that is not on atlassian.net, paste a personal access token from your Jira profile instead of an email and API token. Fogar tries Jira Cloud’s current search endpoint first and falls back to the classic one.

Can the Jira widget change anything?

No. It only runs your search and lists the results. To edit an issue, click it and it opens in Jira.

Install

Add to Chrome

Fogar is on the Chrome Web Store. One click to add it, and it updates itself from there. Then open a new tab.

Add to Chrome

Free, from the Chrome Web Store. Brave, Arc, and Edge install from it too.

On your phone, or not on Chrome? The same Fogar runs as a web app at app.fogar.ai. Open it once with a connection, add it to your home screen (Safari: Share, then Add to Home Screen; Chrome: the menu, then Add to Home screen), and set it up from there; after that it works offline. The widgets that need Chrome’s own APIs, Sessions, bookmarks, Inbox, Feed, Jira, and Agenda, stay on the desktop.

Loaded the zip before the listing went live? The store copy has a different extension ID, so your data will not follow on its own. Three steps move it over.

  1. In your current Fogar, open Settings and click Download a backup.

    Todos, notes, recipes, widgets, sessions, and settings go into one file.

  2. Add Fogar from the store.

    It opens on your next new tab, empty.

  3. Open its Settings and Restore from a backup.

    Once it looks right, remove the old copy in chrome://extensions.

Can't use the store? The same build is here as a zip: unzip it, turn on Developer mode in chrome://extensions, and Load unpacked. It will not update itself.
